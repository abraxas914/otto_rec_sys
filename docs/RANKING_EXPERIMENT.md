# 第一轮学习排序实验协议

## 时间与样本隔离

沿用 reports/first_baseline.json 的固定开发起点 D。所有时间单位为毫秒。

- 训练召回图：10% 样本内事件 ts < D - 7 天。
- 排序训练查询：会话起点属于 [D - 7 天, D)，独立种子 1907 稳定抽样 12%；先删除 ts >= D 的事件，再按严格时间边界截断会话。
- 开发召回图：事件 ts < D。基础图复用 scale10 产物；新增三关系按同一时间边界构建。
- 开发查询：原来 1% 样本内的 18,152 个会话，标签与旧实验逐条一致。
- 复核查询：10% 样本中排除旧 1% 样本，取最后两天开始的会话，独立种子 991 抽样 15%。只有冻结模型后才运行 --audit；不据此调参。

复核集是新会话、较晚时间子窗口，仍与旧开发集共享日历区间和环境；不能称为完全独立的新一周时间外验证。排序训练与所有评估查询不重叠。

训练图看不到任何排序训练查询，开发图看不到任何开发或复核查询。因此查询后缀不能回流到自己的共现或统计特征中。每个查询的特征只来自其可见前缀和相应的历史图。

## 候选和特征

三种额外关系只统计最后 30 个事件：相邻正向事件；正向两小时内到加购/下单；正向一天内购买行为到购买行为。商品必须不同，时间差必须严格为正；采用一小时半衰期。每会话每关系每商品对只保留最大权重，最后每源商品保留 40 邻居。

候选固定最多 200：原基线前 100 + 各新关系前 30，去重后用原基线补齐。固定预算下新增候选可能挤掉原基线 101-200，因此同时报告新增和丢失目标命中。历史规则与特征全部只依赖前缀。

31 个特征：历史行为次数与时间、基线排名、会话统计、历史图热门排名，以及六路来源各自的分数、排名、最后商品关联强度。商品 ID 本身不作为数值特征。

## 学习与对照

每任务独立 LightGBM LambdaRank：120 棵树、15 叶、学习率 0.05、固定随机种子。不用复核集 early stopping。训练保留有正样本的完整候选组，不额外抽负样本；候选没有正样本的组被排除并计数。评估保留全部会话，包括召回失败会话。

对照包括：当前 pooled 规则；各新关系独立加入的规则；完整排序器；候选不变但去掉三路新关系特征的排序器。后者只衡量新特征在相同候选下的作用，不是完整移除新增召回的消融。

LambdaRank 优化的是列表排序代理损失，不等同于官方跨会话微平均 Recall。最终决策仍看官方三任务 Recall@20 与 0.1/0.3/0.6 加权值；不把分数当成行为概率。

## 运行

先准备 data/sample 与 data/sample10，并运行原基线和 scale10。然后：

```sh
python -m otto.rank_experiment
# 冻结候选策略和模型之后，仅做一次新会话复核：
python -m otto.rank_experiment --audit
```

artifacts/rank-v1 缓存特征、图、模型及预测，reports/rank_v1_*.json 保存可发布汇总。改变数据、实现或参数时使用新的 --output 目录，不能沿用旧缓存。
