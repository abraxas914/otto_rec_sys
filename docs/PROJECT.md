# 项目方案

## 1. 三条线，共用数据与实验底座

| 线路 | 决策对象 | 优化/验证 | 交付 |
|---|---|---|---|
| A 比赛复现 | clicks/carts/orders 各一张 Top-20 | 官方 weighted Recall@20 | 强基线、提交文件、消融表 |
| B 决策研究 | 同一个会话的一张共享 Top-20 | 三种行为命中率、覆盖、新颖性、行为相似度代理 | 权重敏感性、经验 Pareto 前沿、约束策略 |
| C 工程原型 | 有版本、可回退的一次推荐请求 | 正确性、延迟、内存、日志、异常恢复 | 本地服务、压测报告、发布决策备忘录 |

A 与 B 是不同任务。A 中三张榜能独立优化；没有共享模型或预算约束时，三种权重并不必然制造排序冲突。B 才强迫同一组曝光位置承担多个目标。不得把 B 的结果直接当成 A 的高低分结论。

## 2. 要产出的个人判断

把以下问题写成假设，实验前记录预期，实验后允许推翻。

| 问题 | 对照实验 | 可以形成的判断 |
|---|---|---|
| 瓶颈在召回还是排序？ | 候选预算 50/100/200/500；计算候选内理想 Top-20 上限 | 增加候选是否比换精排更值 |
| 三种行为真的冲突吗？ | 独立模型、共享模型；分别输出榜与统一榜 | 区分标签相关、共享参数负迁移、列表资源冲突 |
| 0.1/0.3/0.6 是合适的决策权重吗？ | 固定预测器，扫统一列表融合权重 | 比赛权重无法自动解释业务偏好 |
| 静态权重对谁不好？ | 按历史长度、是否有加购、商品频次分层 | 全局改善是否掩盖某些会话受损 |
| 长尾曝光要付多少代价？ | 无重排、频次惩罚、MMR、约束重排 | 给出命中率损失与覆盖变化的曲线 |
| 多任务学习是否值得？ | 同候选与预算下，独立任务模型 vs 共享模型 | 表示共享收益是否超过稀疏订单任务负迁移 |
| 更复杂的模型值得上线吗？ | 效果、模型大小、P95/P99、训练成本联合比较 | 选择可行解，而非仅选离线最高分 |

这些是待验证问题，不是预先写好的结论。多样性与准确率也未必总冲突；可能存在同时改善两者的被忽略方案。

## 3. 分阶段工作及退出条件

### M0 数据与评估（首先完成）

- 明确使用比赛原始数据还是赛后公开研究数据；记录下载来源、版本、文件哈希和授权信息。
- 数据巡检：时间范围、会话数、商品数、三种行为比例、重复事件、时间逆序、会话长度、重复购买。
- 建立时间前移的训练/调参/最终测试窗口；最终窗口只用于定稿评估。
- 写清截断方案：随机种子、时间相同事件的处理、无后续目标会话、冷商品口径。
- 将实现与官方 evaluator 对拍；真实样本完成数据到报告闭环。
- 验收：没有未来特征；标签与预测行完整；指标与官方对齐；同配置复现一致。

### M1 可解释基线

- 按行为热门、会话最近访问、带行为和时间权重的重复访问。
- 共现召回：click-click、click-cart/order、cart/order-cart/order；只读取许可时间内事件。
- 每路记录独占命中、重叠率、增量召回、时间和内存；保留召回来源字段。
- 验收：真实数据消融表；解释热门与重复访问各解决什么问题；量化候选上限。

### M2 强排序与比赛上限

- 先做 LightGBM 排序基线；特征包括会话最近行为、频次、共现强度、召回来源和历史商品统计。
- 训练排序器的候选必须由更早数据生成，采用时间外候选与特征，避免训练目标进入共现统计。
- 分别训练三种行为排序器；记录负采样策略，不把采样分类分数直接解释为 CTR。
- 增加 embedding 召回；只有独占命中或成本收益支持时才保留。
- 序列模型、多任务模型和融合属于后续对照；在同候选/预算下比较，并另报全系统结果。
- 验收：至少两种召回、一个精排；逐项消融、时间窗口稳定性、分层误差和置信区间。

### M3 从三张榜到一张榜（项目主贡献）

- 冻结候选和预测模型；比较 rank fusion、标准化得分融合和经验证校准后的融合。
- 融合分数仅为排序效用；没有曝光分母时不声称得到真实点击概率。
- 扫描非负、和为 1 的行为偏好向量，记录共享列表的 clicks/carts/orders Recall@20。
- 增加新颖性、覆盖与行为向量列表差异度。相似度由训练数据建立，不解释成真实品类差异。
- 分别比较加权重排、MMR、epsilon-constraint；经验前沿只覆盖已搜索策略，不声称全局 Pareto 最优。
- 对被支配解、误差条重叠和不同时间窗口前沿漂移进行分析。
- 进阶：复现 MultiTRON 的偏好条件模型，与后处理融合比较。论文原协议与本项目协议分别报告。
- 验收：读者可选偏好看到列表与指标变化；明确为什么推荐某个工作点及其不确定性。

### M4 服务与约束

- 将离线产物导出为带版本的候选索引、模型和策略配置；提供 recommend 接口与列表解释。
- 处理短会话、未知商品、空候选、模型超时、索引缺失；使用热门候选回退。
- 库存/禁售用独立合成元数据演示，标注 synthetic；先过滤，再补位；候选不足时返回不足原因。
- 约束验证覆盖回退路径；回退不允许重新引入被禁商品。
- 日志包含 request/session ID、可用候选、各路来源、分数、过滤原因、策略与模型版本、耗时。
- 约定机器、候选预算、并发与请求分布，报告端到端 P50/P95/P99、吞吐、峰值内存和降级率。
- 200ms 是可调整的演示服务预算，不是数据集事实；确认部署环境后冻结 SLO。
- 验收：可重复服务演示与压测；策略回退正确；未达 SLO 的版本列明不通过。

### M5 探索与上线判断

- 设计探索流量、可行动作集合与已知 propensity 的日志契约。
- 在合成环境中演示 epsilon-greedy、反馈循环和短期/长期收益差异；做环境假设敏感性分析。
- 若转向真实反事实研究，另建 KuaiRand 实验，先核验该版本随机机制、字段与支持集。
- IPS/SNIPS/DR 仅用于具备相应识别条件的日志；报告 overlap、有效样本量和估计不稳定性。
- 不将短视频结果直接迁移为电商收益；探索不是静态 OTTO 日志能证明的上线增益。
- 产出上线实验设计：随机化单位、主指标与护栏、最小可检测效应、样本量计算、实验周期与停止规则。当前缺少线上基线时保留参数，不杜撰流量。
- 验收：完成“是否值得进入线上实验”的备忘录；无真实线上实验时，不作已改善 GMV/留存的结论。

## 4. 资源和范围

| 档位 | 用途 | 原则 |
|---|---|---|
| 本机 | 数据核验、小规模闭环、评估器、策略与服务 | 先流式处理；抽样覆盖整个训练时间范围，不能取文件前 N 行冒充随机样本 |
| CPU/大内存服务器 | 全量共现、特征、树排序器 | 分区存储、限制会话配对长度、落盘聚合；实测后估算全量成本 |
| GPU | embedding/序列模型/MultiTRON | 强基线完成再投入，记录每次 GPU 小时和收益 |

算力尚未确认，不启动付费计算。数据下载前检查磁盘空间；Kaggle 页面标示约 11.89 GB，不等于解压、索引、特征后的总空间。先估算峰值再跑全量。小样本分数不与全量结果并列比较。

## 5. “完整项目”最终交付

1. 可复现仓库：数据清单、配置、种子、依赖锁、模型产物清单、运行说明。
2. 实验报告：真实分数、召回上限、消融、分层与不确定性、资源成本。
3. 决策报告：共享列表前沿、约束可行性、偏好选择与敏感性。
4. 可交互演示：输入匿名会话，查看三榜/统一榜、策略参数、来源和延迟。
5. 工程报告：数据与服务版本契约、压测、故障回退、监控方案。
6. 个人论文式总结：问题 → 假设 → 对照 → 结果 → 反证 → 决策 → 局限。

收敛标准：每个主要模块都有对照；关键结果可复现；新增复杂度需证明收益；停止条件按事先约定的预算与实验覆盖执行。最终是否选择简单模型取决于证据。
