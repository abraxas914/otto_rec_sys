# 行为序列模型第一轮：未确认增益，保留原方案

日期：2026-09-20。实现与协议先于评估结果提交（e717437），模型摘要在新复核前冻结（d6d9d49）。[协议](../docs/SEQUENCE_EXPERIMENT.md)、[模型与训练摘要](sequence_v1_manifest.json)。

## 结论

在本轮有限训练预算和固定候选协议下，Transformer 特征没有带来可确认的排序增益。开发集上与 PCTM 组合的小幅改善没有在新会话复核中重复出现；不替换现有方案，不据此发布新 Kaggle 成绩。本轮是行为感知的轻量序列实验，不是 eSASRec 完整复现，更不能据此否定所有 Transformer 或生成式推荐方法。

## 实测分数

所有行使用相同的原 rank-v1 候选，每任务最多 200 个；评估包括全部会话与全部标签，不因未知商品或召回失败删样本。

| 方法 | 固定开发集：18,152 会话 | 本轮新复核集：7,093 会话 |
|---|---:|---:|
| 原 rank-v1 排序器 | 0.534274 | 0.547071 |
| 只增加词表已知标志 | 0.534662 | 0.547027 |
| 加入近期池化神经特征 | 0.533718 | 0.546697 |
| 加入 Transformer 特征 | 0.533831 | 0.546915 |
| PCTM 增强排序器 | 0.535393 | 0.548529 |
| PCTM + Transformer | 0.536333 | 0.548250 |
| 仅池化神经分数排序 | 0.309350 | 0.307751 |
| 仅 Transformer 分数排序 | 0.307393 | 0.311106 |

复核集取预先规定的 seed=991 哈希 [0.30,0.45)，排除原 1% 开发样本；前两轮 [0,0.30) 不再被称作新复核集。全部神经权重与排序器在查看本轮复核结果前冻结。两套数据仍共享同一周环境，不是新的自然周。不能与上一轮不同会话集合的绝对分数直接比较，也不能与 Kaggle 分数直接比较。

## 不确定性

下表为差值及 1,000 次配对会话 bootstrap 的 95% 区间。

| 比较 | 开发集 | 新会话复核 |
|---|---|---|
| Transformer − 原排序器 | -0.000443 [-0.002247, 0.001486] | -0.000156 [-0.002880, 0.002312] |
| Transformer − 池化增强 | +0.000113 [-0.001324, 0.001745] | +0.000218 [-0.001950, 0.002374] |
| 组合版本 − PCTM | +0.000940 [-0.000743, 0.002635] | -0.000280 [-0.002982, 0.002374] |

全部区间跨零。主比较预先定义为 Transformer 增强 vs 原 rank-v1；其余为诊断性比较。没有多重比较校正，重采样也没有覆盖时间/商品关联和自适应选模的不确定性。不能把“不显著”解释为两种方法完全等效。

## 具体学到了什么

1. **词表覆盖与任务覆盖不同。** 历史中 200,000 商品覆盖约 80.05% 的事件，但开发集真实目标的覆盖只有点击 69.20%、加购 64.31%、下单 67.87%；新复核分别为 68.57%、65.43%、66.86%。这些比例按会话内唯一目标计数，不是官方 capped Recall 上限。候选大多在词表内，不代表正确目标也被覆盖。
2. **购买监督尤其稀疏。** 开发集 3,249 个原始唯一下单目标计数中，1,044 不在词表，另有 870 虽在词表却未在本轮训练数据中作为下单正例出现。两者合计约 58.9%。它们仍可能从点击、历史输入或其他行为获得迁移信号，但不能假定已获得足够购买监督；“有商品向量”不等于“学好了购买表示”。
3. **复杂编码尚未胜过轻量编码。** Transformer 增强相对池化增强的差值很小，区间跨零；单独用两种神经分数排序都只有约 0.31。这里没有证明注意力在现有强关系特征之上学到了额外且可靠的信息。
4. **长会话没有显现明确优势。** 描述性切片中，超过 20 个前缀事件的 Transformer 增强得分在开发集与原模型相同，复核略低。未对切片单独检验显著性，不能把小幅波动当作场景定论。长度切片的微平均分数不能按会话占比简单还原总分。
5. **组合增益需要复核。** PCTM+Transformer 在开发集比 PCTM 高约 0.00094，新复核却低约 0.00028。若仅看开发集最优点，容易把波动写成进步。

以上是诊断线索，不是失败原因的因果证明。词表截断、只抽一个前缀、三轮训练、模型冻结较早、候选限制、排序器容量和代理损失都可能影响结果。

## 做了哪些实际工作

- 用严格时间切分的 389,324 个历史前缀构建 407,092 个分行为训练组；训练词表和标签全部早于排序训练窗口（最大事件时间 1660514390577 < 1660514390707）。
- 实现商品、行为类型和相对时间输入；近期池化对照与两层两头 Transformer；三个目标行为头与共享商品向量。
- 批内目标加均匀负例的对比训练，屏蔽同任务全部已知正商品。每轮从多正例集合随机取一个正例，不宣称无偏全词表 softmax。保留历史商品与重复购买。
- 固定候选和原有 31 特征，逐行检查训练缓存一致；训练词表标志、池化、Transformer、PCTM 组合的排序对照。开发集原 rank-v1 和 PCTM 基准结果与前轮完全一致。
- 在 Apple MPS 上实际训练：池化约 92.4 秒、Transformer 约 128.7 秒，各三轮。参数约 1,282 万/1,288 万，大部分来自商品表。损失下降但未做收敛性证明。
- 全版本开发评估约 153.7 秒，新复核约 61.1 秒，包括两种神经编码与八套输出；这不是单模型线上延迟，也不是 P99 服务测量。
- 解决 GPU 特征生成与 CPU 排序混用进程时的原生崩溃，训练和推理均隔离运行。30 项测试通过；没有改动本轮数据或模型参数来绕过失败。

## 下一步的研究决策

优先改变可获得的训练信息，再比较架构：

1. 在新的独立实验目录中，增加严格时间内的多前缀/逐位置训练监督，对比只有一次会话切分的版本；先证明监督密度的作用。
2. 单独扩大词表或使用有明确碰撞控制的长尾表示，并保留未知商品回退；将词表规模与训练轮数分开消融，不能一起改后归因于某个因素。
3. 使用滚动时间折产生排序训练用的神经分数，再为评估训练较新的快照，避免“排序训练泄漏”与“模型过旧”二选一。直接用看过排序标签的神经模型生成训练特征不可接受。
4. 排序增益和向量召回增益分别验证。本轮没有做向量召回，不能据此判断它是否能补足现有候选缺口。

暂缓更深 Transformer、HSTU 内核迁移和生成式语义 ID。这里暂缓的是投资优先级，并不是宣判这些研究路线无效。已看过的新复核集也必须标为已知数据，后续若继续选参，要采用新的验证安排。

当前已验证 Kaggle 成绩仍为 v2 Public **0.54340** / Private **0.54352**。本轮没有提交。
